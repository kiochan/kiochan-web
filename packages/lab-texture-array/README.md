# Texture Array

An original, local-first seamless texture editor maintained in `packages/lab-texture-array`. Open it at `/lab/texture-array`; the host owns navigation, theme, metadata, and the Lab sidebar. The focused `/lab/texture-array/app` workspace reuses the same editor/runtime and browser-local project as the overview route, with a compact heading, wider working area, and independently scrollable desktop inspector. Shared website navigation and Lab sidebar remain present. No external motif assets or user reference images ship with the package.

## Editing

The editor accepts an optional `translate(message)` prop, with English as the server-rendered default. The host connects Chinese copy from `apps/web/src/content/site.ts` to its existing language switcher. Controls, accessible labels, explanatory copy, export progress, common errors, and stored history labels are translated at display time. Source filenames and serialized project/history data remain unchanged. Switching languages does not recreate the renderer or reset the design. Japanese and German currently retain the editor's English fallback. `scripts/localization.test.mjs` checks Chinese message coverage, placeholders, and history/progress formatting.

Import multiple PNG, JPEG, or WebP images using Add images or by dropping files anywhere in the editor outside a layer row. Dropping a single image on a layer row replaces that specific layer, even when another layer is selected; its displayed name and settings are preserved. Drag highlights distinguish adding from replacement. Multiple files dropped on a layer are rejected without changing the project. Both paths share format, size, source-budget, decode, history, and local-only handling; a batch is applied only after all files validate. Drops are blocked while files or exports are processing. Each image becomes an independent layer with aspect-preserving size, rotation, opacity, column/row counts, tile-relative offsets, and alternating-row stagger. The half-drop preset uses even rows to maintain its rhythm across seams. Later layers composite over earlier layers; layers can be hidden, reordered, duplicated, or removed.

Replace image changes only the selected layer’s source, preserving all array settings, visibility, and stack order; duplicate layers keep their own source. Undo/redo and saved projects retain both images within the existing 12-source and source-byte budgets. Each array setting has a slider and a numeric input. Numeric edits apply on blur or Enter, allowing intermediate empty, negative, and decimal input; Escape restores the current value. Valid values are clamped on completion, and invalid or empty edits restore the current value. Sliders update the design immediately.

Copy parameters takes an in-memory snapshot of the selected layer’s columns, rows, independent spacings, size, image/array angles, offsets, stagger, opacity, and sampling. Select another layer and Paste parameters, or Paste to all layers. Image sources, names, visibility, stack order, and output resolution stay unchanged. A paste creates one undoable history state, including a batch paste; unchanged values do not add history. The parameter clipboard stays available across project switches in the same mounted editor and is discarded when leaving the editor.

Array angle requests a direction independently from image rotation. The editor fits a uniform periodic lattice to the square tile, instead of rotating and wrapping a finite rectangular cluster. This removes the triangular voids and clumps caused by the former algorithm. Integer reciprocal frequencies make both square edges exact periods of the same lattice. Requested angles, counts and stagger describe target spacing; the fitted angle and number of motifs are shown in the inspector and may differ. For example, 4 × 4 at 45° becomes 18 uniformly spaced motifs with an exact 45° direction. Arbitrary angles cannot all be represented exactly by a low-density square-periodic lattice. The solver examines 81 nearby integer matrices and preserves basis direction, spacing, and density as closely as possible while rejecting singular layouts. Each tile has at most 2048 centers. Enumeration is bounded, duplicate-free at seams, and cached per layer; it never expands or animates continuously.

Sharp image scaling uses bounded Catmull–Rom reconstruction when enlarging, transitioning to trilinear mipmap filtering when reducing, with up to 8× anisotropic filtering when supported by the GPU. Source bitmaps and mipmaps are premultiplied before filtering to prevent dark transparent fringes; export readback returns straight-alpha pixels. Pixel mode uses exact nearest texels for hard edges and may alias when reduced. Magnified canvas inspection displays output pixels without a second smoothing pass. These algorithms preserve available detail; they cannot reconstruct detail missing from the uploaded raster. Every render samples the original uploaded texture, never a previously resized output.

Saved projects use version 4 to preserve independent spacing. Version 1, 2 and 3 projects upgrade their history and retain sources and requested settings, defaulting missing spacing values to 100% on each axis. Version 1 layers receive zero array angle and Sharp sampling. Older diagonal projects render with the corrected lattice after upgrading, so their motif positions and counts can change. Version 4 files require this updated editor.

The square output is a periodic tile. Instances crossing an edge wrap to the opposite edge. A finite 3 × 3 check previews nine copies, with guide lines excluded from export. Drag the viewport or use focused arrow keys to pan within fixed bounds. Plus/minus change zoom and Home/Fit restores the view. View changes never alter the design. Transparent areas use a theme-aware checkerboard.

Export offers layered PSD and PNG ZIP at 1–4096px. Both formats bake each editor layer into one full-tile raster, including repeated instances and per-instance opacity. Layers can be renamed in the inspector; Enter or blur applies a trimmed, non-empty name of up to 200 characters, and Escape cancels. Names are preserved in history, saved projects, duplication, image replacement, PSD layers, and the PNG ZIP manifest. Older projects without names remain supported. Unnamed exported layers use deterministic English names (`Layer 01`, `Layer 02`, etc.) in bottom-to-top editor order. ZIP filenames always remain numbered, so duplicate names and path characters cannot overwrite files or create archive paths. PSD is written by `ag-psd`, preserves straight-alpha layer pixels and hidden flags, and includes a merged composite. PNG ZIP uses `fast-png` and `fflate`; it contains `Layer-01.png`, etc. (including hidden layers), `Composite.png` (visible layers only), and `Layers.json` with English names, stack order, dimensions, and visibility. PNG files preserve RGBA pixels, including hidden RGB beneath zero alpha. PSD composite RGB uses the library's compatibility matte; layer pixels retain original alpha. No TIFF export remains. Encoders run in a dedicated cancellable worker. PSD retained raw pixels and ZIP encoded PNGs are limited to 512 MiB; large layered exports may require a smaller tile size. Files remain local to the browser and are not uploaded. Photoshop application compatibility still requires real-editor verification. Save project downloads a versioned JSON containing original image bytes, layer settings, the current history position, and up to 100 snapshots. Open project restores these snapshots for further undo/redo. A new edit from an earlier snapshot replaces its redo branch. Images remain embedded even when removed from a layer so undo can recover them. Nothing is uploaded. Projects automatically save in browser-local storage; use Save project for a portable backup before clearing browser data or starting a new project.

Horizontal and vertical spacing are independent 50–400% multipliers of the Columns/Rows baseline. They act along the rotated array axes and do not resize images or change image rotation. 100% restores the previous spacing. Increasing one axis spreads its centers while preserving the other requested pitch. Reset spacing restores both multipliers without changing the other controls. The solver displays fitted X center pitch and perpendicular Y row pitch as percentages of the tile; discrete square-periodic fits can adjust actual spacing and angle. Dense requests above 1024 target motifs per tile are reduced proportionally on both axes before fitting, preserving their pitch ratio and the 2048-instance cap. Density limiting is reported in the inspector. Spacing is included in the per-layer geometry-cache key, edit history, saved project, preview and exported layers.

## Layer controls and output size

The layer panel shows local source thumbnails, names, stack positions, a selected-row highlight, and independent visibility buttons. Selecting a row edits that layer; dropping one image on the row, including its visibility control, retains the existing replacement behavior. Image actions and the parameter clipboard are grouped separately, with decorative inline SVG icons beside text labels. Destructive removal has a semantic danger color. Array controls can be collapsed. Icon-only buttons have translated accessible names and tooltips, and touch controls remain at least 44px tall.

Export size accepts any integer square side from 1 to 4096 pixels, including non-power-of-two sizes such as 777 or 1500. Enter or blur applies the number; empty/invalid edits restore the current value, numeric values are rounded and clamped to the supported range, and Escape cancels. Preset buttons remain available. The preview, PSD, PNG ZIP, saved projects and undo/redo all use the same size. Existing version-4 projects remain readable; projects saved with custom sizes need this updated editor. GPU allocation and the existing export memory budgets still apply.

## Multi-layer editing and browser persistence

Each row has a 44px checkbox label. Checked rows define parameter-edit targets; clicking a row selects a single active layer and clears the checks. Name/image/duplicate/remove actions affect the active layer, while array controls affect checked layers. If any of the twelve copied parameters differ, shared controls are disabled and dimmed. The explicit Confirm and sync selected layers button copies the first checked layer in bottom-to-top list order to all checked layers in one undoable edit. Identical settings can be adjusted together immediately. Image/name/visibility differences do not count as mixed parameters. Clear selection returns to single-layer editing. Selection itself does not modify the project.

Both editor routes restore and debounce-save the complete project, including embedded images, history and cursor, under the browser-local `kiochan-texture-array-project` key. Restoration finishes before editing or autosave begins. Workspace/overview links flush pending work before navigating and stop if saving fails. Page exit and component cleanup flush pending saves. An unreadable saved copy is preserved until the user explicitly opens a JSON project, starts a new project, or chooses Replace saved copy. Browser storage may be disabled or have a quota smaller than the project's source budget; failures remain visible and Save project provides a downloadable fallback. Local storage is browser/origin-specific, not cloud backup, and concurrent tabs use the last successful save. Clearing browser data removes this copy. Original PSD files are not retained, only selected raster sources.

## PSD import

Import PSD opens a local file picker; dropping a single `.psd` anywhere in the editor opens the same layer selector. Dropping it on an existing layer limits selection to one replacement and preserves that layer's name and settings. The selector shows nested group paths, pixel dimensions, hidden status, and unavailable layers. Select individual layers or use Select available (bounded by remaining project capacity); nothing changes until Import selected layers succeeds. Escape or Cancel PSD import discards the pending document and terminates its worker.

The importer accepts PSD version 1, 8-bit RGB, up to 70 MB, 8192px per document/layer side and 32 megapixels. PSB, CMYK, and higher bit depths are rejected. Documents are bounded to 256 layers and 32 nested groups. The worker reads compressed channel metadata first and decodes only selected raster layers, in bottom-to-top document order. Each layer becomes a PNG source retaining its own pixel bounds, alpha, name, and baked individual opacity. Hidden layers can be selected and start visible. Group compositing, masks, effects, adjustment rendering, blend modes, and document positions are not reproduced; this is an image-source importer, not a Photoshop document renderer. Group entries are not selectable. Layers without usable pixels or exceeding source dimension limits are unavailable. The existing 12-source, 12-layer, 8 MB per-image and total source budgets apply, including sources retained for undo. The original PSD is not embedded in saved projects; only the selected raster PNGs are saved. Parsing and encoding run in a cancellable worker with a 60-second request timeout, and no PSD is uploaded.

`node --test scripts/texture-array-psd.test.mjs` verifies nested/hidden layer listing, selected-only imports, stack order, exact RGBA/opacity, source-name and project round trips, invalid selections, unsupported headers and empty layers. CI runs this suite alongside existing engine checks.

## Rendering and limits

`src/renderer.ts` uses WebGL2 GLSL shaders and instanced quads (one array draw per visible layer, using a small instanced position buffer). Nine bounded wrap copies per instance cover the neighboring tiles. The longest motif side is capped at 70% of the tile, so a rotated motif cannot extend beyond the supported wrap neighborhood. A framebuffer stores the tile; a second shader samples it for the finite repeat preview. Textures have mipmaps. Rendering is driven by design/view-mode changes; there is no animation loop, and pan/zoom only change CSS transforms. GPU textures, framebuffers, programs, decoded bitmaps, and download URLs are released. Context restoration recreates GPU resources from retained originals.

Projects allow 12 source images and 12 active layers, up to 8 MB per uploaded image and approximately 48 MB total source bytes. Decoded images are limited to 8192px per side and 32 megapixels, and must fit the device texture limit. Target counts are bounded at 32 × 32 per layer; fitted periodic layouts are capped at 2048 centers. Project imports validate schema, sizes, finite numeric bounds, source references, and raster-only data URLs before replacing the current project. The renderer reports unsupported WebGL2 and GPU allocation failures. High-overlap arrays and 4096px output can still be expensive on low-end devices; no device-independent frame-rate guarantee is made. Source files stay intact, while exported layers are raster resamplings of the edited layout.

## Verification

- `node --test scripts/texture-array.test.mjs` checks history branching, source preservation, and untrusted project validation.
- `pnpm lint`, `pnpm typecheck`, and `pnpm build` check workspace integration.
- `node scripts/smoke-test.mjs` checks the production route, Lab catalogue, shared chrome, and sitemap.
- Browser verification should cover transparent multi-image import, asymmetric image orientation, overlapping alpha, edge wrapping, PSD layer channels, PNG ZIP pixels, visibility and order, single/3 × 3 export equivalence, cancellation, saved project restoration, keyboard and touch navigation, context loss, and narrow/light/dark layouts.

PSD encoding follows the maintained [ag-psd](https://github.com/Agamnentzar/ag-psd) library. PNGs use [fast-png](https://github.com/image-js/fast-png), and archives use [fflate](https://github.com/101arrowz/fflate). Run `node --test scripts/texture-array-export.test.mjs` for PSD layer/alpha round trips and exact PNG ZIP decoding checks.
